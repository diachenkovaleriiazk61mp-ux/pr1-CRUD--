# Виправлення після перевірки

- Додано перевірку open-loop: фактична відправка не менше 98% цілі та p95 dispatch lag не більше 100 мс. Невалідний результат зберігається, але сценарій завершується з помилкою.
- Типова кількість потоків збільшена до 256 на процес. Це налаштування, а не гарантія: якщо перевірка не проходить, треба збільшити --threads або звільнити ресурси хоста.
- Новий експеримент архівує попередню серію в history/, щоб не змішувати старі та нові числа.
- Звіт генерується з фактичних файлів, показує відставання генератора, кількість одночасних запитів закритого контуру і відмінність фінального образу від образу старої серії.
- Старі 500-rps результати та їхні S/e й порівняння контурів позначено діагностичними; вони потребують повторення.
- Додано однокомандний запуск Linux/macOS start.sh.

## Як завершити на Windows

1. Встановіть/запустіть Docker Desktop у режимі Linux containers та Python 3.11+.
2. Відкрийте PowerShell у корені цього проєкту.
3. Виконайте `python scripts/experiment.py --reset-lab-data`. Ця команда видаляє дані саме цієї лабораторної, як потрібно для перевірок порожньої бази.
4. Якщо генератор не пройшов перевірку, повторіть `python scripts/experiment.py --reset-lab-data --threads 512`.
5. Після успішної серії перевірте REPORT.md і завантажте оновлені файли та results/ у GitHub.

Повну Docker-серію користувач виконала на Windows 2026-10-14 з --threads 512 та Python -X utf8. Отримані results/ перевірено; цифри не підмінено. У цій готовій копії повторно виконувати вимірювання перед здачею не потрібно.

## Фінальна перевірка

У текстових записах сценарію задано UTF-8. Таблиці Markdown виправлено; висновки узгоджено з новими sent_rps, success_rps, помилками й фактичним p95 закритого контуру. Папка history/ не входить у поточну здачу.
